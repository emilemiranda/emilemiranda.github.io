NYC Healthcare Accessibility

An end-to-end Python GIS workflow that combines healthcare facility locations with local U.S. Census ACS Summary Files to estimate tract-level coverage, classify underserved census tracts, and generate candidate locations for further review.

Project overview

This project evaluates healthcare accessibility across New York City’s five boroughs using a reproducible workflow built around locally stored census tables and spatial processing. Its distinguishing implementation choice is that the primary analysis reads ACS Summary Files from disk instead of making live Census API requests during the analysis run.

Project question: How do healthcare facility locations relate to tract-level demographic need and estimated coverage, and which census-tract centroids should be reviewed as candidate areas for future healthcare investment?

The workflow keeps facilities, census geography, demographic attributes, coverage outputs, and candidate sites as reusable GIS layers so the analysis can be inspected in ArcGIS or QGIS.

Data and sources

  • NYC Open Data: healthcare facility locations across New York City.
  • U.S. Census Bureau: local ACS 5-Year Summary Files, including B01003 (population), B19013 (median household income), and B25003 (housing tenure).
  • ACS geography reference: Geos20235YR , as listed in the project documentation.
  • TIGER/Line: 2024 census tract boundaries.

The project notes do not give an exact NYC Open Data dataset title or an additional release date for the facility locations. Preserve those details in the repository’s data-source record when preparing a fresh run.

Method and workflow

  1. Acquire inputs. Download the NYC healthcare facility dataset, local ACS Summary Files, and TIGER/Line tract boundaries.
  2. Prepare the records. Standardize facility attributes and geometries, construct tract GEOIDs, merge ACS tables, and convert demographic fields to numeric types.
  3. Align the spatial data. Project the input layers into a common coordinate system suitable for spatial measurement.
  4. Build need indicators. Calculate population density and renter occupancy rates, then generate standardized demographic-need scores.
  5. Estimate coverage. Create one-mile hospital buffers and estimate healthcare coverage by census tract.
  6. Classify and rank candidates. Mark tracts with high demographic need and low coverage as underserved under the project’s criteria; generate candidate locations from tract centroids ranked by priority.
  7. Export reviewable outputs. Produce tabular, GIS, and hosted/web deliverables.
Method distinction: the project describes one-mile spatial buffers. These should not be presented as network-based walking or driving travel times unless a separate network analysis has been performed.

What the outputs support

  • Tract-level comparison: each tract can be examined alongside population, median household income, population density, renter share, coverage percentage, and a composite healthcare-need score.
  • Transparent underserved classification: the workflow identifies tracts where the chosen demographic-need measure is high while estimated healthcare coverage is low.
  • Candidate-site screening: centroid-based candidate locations provide places for follow-up analysis, not automatic facility siting decisions.
  • Reproducible local inputs: once the required source files are in place, the main run does not depend on a live Census API request or its rate limits.

The project summary does not include the final number of underserved tracts, coverage percentages, or specific candidate rankings. Those values should be reported from the saved output tables rather than estimated for this narrative.

Outputs and deliverables

  • Clean healthcare facility dataset.
  • Census-tract demographic dataset.
  • Healthcare coverage polygons and coverage indicators.
  • Underserved census-tract classifications.
  • Candidate healthcare locations generated from ranked tract centroids.
  • ArcGIS outputs: CSV, GeoJSON, Shapefile, Hosted Feature Layers, and a Web Map.
  • QGIS GeoPackage containing Hospitals, Census Tracts, Coverage Areas, and Candidate Sites.
  • Publication-ready maps.

Assumptions and limitations

  • Buffer interpretation: one-mile buffers are geometric proximity zones unless network travel analysis is added.
  • ACS uncertainty: ACS estimates have sampling uncertainty; retain the relevant estimate metadata when interpreting small-area differences.
  • Geographic vintage: ensure tract boundaries and ACS geography identifiers are compatible before joining and comparing areas.
  • Area-level interpretation: a tract summary does not mean every resident has the same level of access.
  • Site selection is multi-factor. Actual siting also needs factors such as transport networks, facility capacity, operating cost, demand, and suitability constraints.

Next steps

  • Publish the exact coverage denominator and the threshold/standardization rules used for the need score.
  • Add verified counts for tracts evaluated and classified as underserved.
  • Test network-based travel-time accessibility and multi-criteria candidate-site suitability.
  • Expand the set of ACS indicators where a clear rationale and data provenance are available.
  • Document the local ACS files and source facility dataset so another analyst can reproduce the input snapshot.
