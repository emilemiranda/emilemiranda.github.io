Flood Exposure Mapping

A reproducible Python GIS workflow that clips prepared spatial layers to a study area, constructs 100 m, 250 m, and 500 m distance bands, and joins building footprints to those bands for exposure screening.

Python GeoPandas Shapely GeoJSON Projected CRS Spatial joins

Project overview

This project demonstrates a focused, reproducible geoprocessing workflow for screening buildings against defined spatial criteria. The documented workflow uses a study-area polygon, checks coordinate reference systems, constructs 100 m, 250 m, and 500 m distance bands, matches building footprints to the bands, and exports the resulting layers.

Project question: Which building footprints meet the chosen spatial exposure criteria within the study area, and how can the result be exported as separate distance bands and a combined review dataset?

This is an exposure-screening workflow. It does not, by itself, estimate flood probability, expected damage, or financial loss.

Data and sources

  • Building layer: Edificaciones. Recintos de edificación , listed from datos.gob.es / IDENA in the project notes.
  • Flood-related source: Zonas inundables. Periodos de retorno del SNCZI , listed from datos.gob.es / Navarra.
  • Study area: a custom polygon used to limit processing to the target area.
  • Outputs: GeoJSON files for risk/distance bands and matched building features.
Data/methodology distinction to preserve: the supplied notes name an SNCZI flood-zone dataset and also describe buffering watercourses into 100 m, 250 m, and 500 m bands. These are not automatically the same geometry or meaning. The final repository and map legend should clearly state which input was buffered and should not label generated distance bands as official flood zones unless the source methodology supports that.

Method and workflow

  1. Load prepared layers. Load building footprints, the flood-related input, and the study-area polygon.
  2. Validate spatial reference. Confirm the layers use a compatible projected CRS in meters before distance calculations.
  3. Clip to the study area. Restrict processing to the selected analysis boundary to reduce unnecessary geometry work.
  4. Create distance bands. Generate the documented 100 m, 250 m, and 500 m buffers around the watercourse geometry described in the workflow.
  5. Join buildings to bands. Use spatial joins/intersections to assign building footprints to the corresponding band outputs.
  6. Export and inspect. Export separate GeoJSON layers, consolidate the combined building output, and create a quick map for visual verification.

What the outputs demonstrate

  • Study-area clipping reduces unnecessary processing. Limiting the geometry early makes the workflow lighter on memory and CPU for the defined study.
  • Separate distance bands support comparison. Outputs for 100 m, 250 m, and 500 m make the effect of the chosen distance assumption visible.
  • Structured outputs make review possible. Keeping each band and the combined building dataset separate supports inspection, remapping, and downstream screening.

The supplied project description does not provide final feature counts per band, so no building total or risk ranking is asserted here. The buffer bands should be interpreted as distance-based screening outputs, not as official flood-return-period zones.

Assumptions and limitations

  • Buffer distances are analytical assumptions; they are not substitutes for an official flood-hazard classification.
  • Building footprints may intersect more than one distance band, so the workflow should state whether overlaps are retained or assigned to one exclusive band.
  • Invalid geometry, CRS mismatch, boundary slivers, and source positional accuracy can affect spatial joins/intersections.
  • Exposure does not establish damage probability, building vulnerability, flood depth, or expected loss.
  • The provided notes do not specify an exact study-area name, CRS identifier, feature counts, or retrieval dates; those should be recorded with the saved outputs.

Next steps

  • Add a map with source credits, study-area boundary, legend, projected CRS, and dataset dates.
  • Publish verified feature counts for each band from the exported GeoJSON files.
  • Resolve and document the precise relationship between the named SNCZI source and the watercourse buffer geometry.
  • Decide how to handle buildings that fall into multiple bands, and write that rule into the method documentation.
  • Consider packaging source layers in GeoPackage to reduce missing-file issues common with multi-file Shapefiles.
