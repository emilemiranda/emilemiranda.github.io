Spain Healthcare Accessibility & Ageing Vulnerability

A VS Code-ready, notebook-led GIS workflow for combining municipal boundaries, healthcare and social-resource services, and INE population-by-age data into healthcare accessibility and ageing-vulnerability indicators across Spain.

Python WFS IGN/CNIG sigMayores INE GeoPackage CSV Jupyter

Project overview

This project is organized as a repeatable data workflow rather than a one-off map. It combines public geospatial services with demographic attributes, standardizes those inputs, builds municipality-level indicators, performs hotspot mapping, and exports both analytical tables and an interactive HTML map.

Project question: How can healthcare/social-resource information and population-by-age data be brought into a reusable municipal workflow for exploring healthcare accessibility and ageing-related vulnerability across Spain?

The repository includes five ordered notebooks and reusable helper scripts so data discovery, acquisition, cleaning, indicator construction, mapping, and export can be inspected step by step.

Data and sources

  • IGN / CNIG: administrative boundaries accessed through WFS.
  • sigMayores: healthcare-resource WFS and social-resource WFS.
  • INE: population by sex and age, year by year.

The project notes do not specify exact WFS layer IDs, retrieval dates, or a single data vintage for all INE tables. These should be captured for each run in the source registry/configuration rather than filled in by assumption.

Method and workflow

  1. Discover the sources. Run notebooks/01_data_discovery.ipynb to inspect source layers and determine the needed configuration fields.
  2. Download inputs. Use notebooks/02_download_raw_data.ipynb and the WFS helpers to retrieve the required data.
  3. Clean and standardize. Run notebooks/03_clean_standardize.ipynb to normalize attributes, types, identifiers, and spatial references.
  4. Join and build indicators. Run notebooks/04_join_build_indicators.ipynb to join source attributes and construct municipal indicators.
  5. Map spatial patterns. Run notebooks/05_hotspot_mapping.ipynb to produce hotspot-mapping outputs.
  6. Export products. Use the reusable export scripts to write CSV, GeoPackage, static map, and interactive HTML outputs.
Configuration requirement: after Notebook 01, set BOUNDARY_LAYER , HEALTH_LAYER , SOCIAL_LAYER , MUNICIPALITY_CODE_COL , and MUNICIPALITY_NAME_COL in scripts/config.py , then rerun from Notebook 02 onward.

What the outputs support

  • Municipal comparisons: joined attributes and constructed indicators provide a consistent structure for comparing healthcare-resource and ageing-related patterns between municipalities.
  • Hotspot exploration: the notebook chain includes hotspot mapping, making spatial clusters and outliers available for review under the configured analysis settings.
  • Multiple ways to inspect results: tabular CSV outputs, a GeoPackage, a static map, and an interactive HTML map support both visual review and reuse in a GIS.
  • Priority review output: the workflow writes top_20_vulnerable_municipalities.csv ; the municipalities and scores should be quoted from that actual saved file rather than recreated from memory.

No specific municipality ranking or index value is stated here because the project notes list the output artefact but do not include the saved ranking values.

Outputs and deliverables

  • data/processed/municipality_vulnerability.gpkg
  • data/processed/municipality_vulnerability_attributes.csv
  • data/outputs/top_20_vulnerable_municipalities.csv
  • data/outputs/vulnerability_index_map.png
  • data/outputs/interactive_vulnerability_map.html

Reusable scripts

  • scripts/config.py — paths, source URLs, and layer/field configuration.
  • scripts/data_sources.py — source registry.
  • scripts/wfs_utils.py — WFS download helpers.
  • scripts/population_utils.py — population-data parsing.
  • scripts/analysis_utils.py — index and hotspot analysis.
  • scripts/plotting_utils.py — map export.
  • scripts/export_utils.py — CSV and GeoPackage export.

Assumptions and limitations

  • Service provenance: WFS endpoints, layer IDs, schema, pagination, and availability can change; preserve the source URL, retrieval date, and selected layer on each run.
  • Municipal scale: municipality-level indicators can hide variation inside a municipality.
  • Hotspot settings: results depend on the chosen indicator, spatial weights/neighborhood definition, and significance settings.
  • Data vintage: INE year-by-year population data and public resource layers may refer to different reference dates; record those dates before interpreting them together.

Next steps
